# Site audit — October 12, 2026

Scope: website source and lockfile, production HTTP behavior, seven routes on
production and localhost, and GitHub repository security settings. Target:
WCAG 2.2 AA; security findings categorized using OWASP Top 10:2025, with
OWASP ASVS 5.0.0 as verification guidance. This is a technical audit, not a
conformance certification or penetration test.

## Evidence and coverage

- `npm run build` passed, generating seven pages; `git diff --check` passed.
- Browser checks used Chromium via Playwright and local axe-core 4.14.0.
  Seven routes were sampled on localhost and production at 1280, 390, and
  320 CSS pixels: 42 automated samples, plus focused keyboard and consent checks.
- Each page has one H1, a unique title/description, canonical metadata, language,
  and image alternatives. Home, About, catalogue, and book detail JSON-LD was
  inspected in the rendered browser; the author entity remains linked.
- Robots and both sitemap files returned 200. HTTP and www variants redirected
  to the preferred HTTPS origin with 308. An unknown URL returned 404; the
  directly addressable `/404` document returned 200 with noindex and is excluded
  from the sitemap. No soft-404 defect was established for unknown URLs.
- Static production responses include CSP, HSTS, nosniff, frame protection, and
  referrer policy. `GET /api/contact` returns 405 but lacks those security headers.
- Local mocked Function checks reproduced an exception for JSON `null` before
  verification. No live mail was sent, and no oversized payload was sent to production.
- Contact hint text `#78849a` on `#131d30` measured 4.46:1 at 12px; AA requires
  4.5:1. The consent privacy link measured 1.13:1 against surrounding text and
  has no persistent underline or other non-color cue.
- Production contact scroll width became 337px at a 320px viewport after the
  Turnstile widget initialized; hiding only that widget restored it to 320px.
- Keyboard checks reached navigation and banner actions; mobile menu state and
  first link focus behaved as expected. No focused control was fully obscured
  by the banner in the exercised tab paths.
- No GA request occurred before consent; accepting requested the tag; withdrawal
  persisted denial and reloaded without the tag. Analytics requests were
  intercepted to avoid recording audit visits. Actual GA delivery was not tested.
- Axe's repeated `landmark-unique` best-practice warning concerns repeated author
  profile navigation with the same purpose and links. It was not promoted to a
  WCAG defect: repeated navigation with the same purpose can share a label.
- GitHub settings confirmed secret scanning and push protection enabled,
  dependency alerts and security updates disabled, and no main branch protection
  or repository rulesets. No repository settings were changed by this audit.

## Current security context and limitations

ASVS 5.0.0 and OWASP Top 10:2025 provide the current verification/risk framework.
Recent advisories emphasize build tooling and native image processing: the locked
Astro 6.4.8 / Sharp 0.34.5 combination matches the malicious AVIF advisory;
exploitation requires processing an attacker-controlled image. This site builds
trusted local assets and serves static output, so the advisory severity does not
prove a public production RCE. Locked Vite 7.3.6 clears the reviewed Vite file
access advisories. Registry checks found Astro 7.3.8, astro-icon 1.2.0, and
axe-core 4.14.0. The upgrade should be tested as a migration rather than forced
through an automatic major-version fix. Current OWASP and Cloudflare guidance
supports bounded parsing, strict input validation, fail-closed verification,
explicit service deadlines, and security headers on Function responses.

This review did not inspect Search Console, ranking/traffic data, field Core Web
Vitals, full assistive-technology behavior, TLS protocol negotiation, dashboard
WAF rules, hosting secrets, or provider log/alert settings. Automated accessibility
passes and keyboard checks cannot establish full WCAG conformance. The source
review found no committed credentials, but a dedicated full-history secret scan
was not performed. Runtime findings are tracked for remediation; this audit did
not change public page copy, dependencies, endpoint behavior, or deployment settings.
